## 1. 结论

| 项 | 结论 | 说明 |
|---|---|---|
| G1 树外 Typert Remote 生成 | **部分可行（需降级路径）** | 生成器硬性要求 `@deepseek-ai/dsh-typert-protocol` 位于 `<root>/packages` 并依赖 vendored cordis 源码；纯树外工作区无法满足。改用「基座 checkout 内生成、运行时树外安装」后，Host 注册 + 客户端调用全链路通过 |

| 安装 / 禁用 / 卸载 | **通过** | `dsh plugin add` → `--dump-config` 出现两行 → profile patch 置 `disabled: true` → `remove` → 行与 manifest/lock 全部清理 |

**Go**：按降级路径进入 P3/P4。每个插件发布前必须在与运行 Host 同版本的 DSH checkout 内生成 artifacts。

## 3. G1 证据与限制

### 3.1 生成器为什么拒绝纯树外

- `WorkspaceTypertGenerator` 从 `<root>/tsconfig.host.json` 的 project references 发现包，并要求包根位于 `<root>/packages`（`analyzer.ts` 的 `isWithin(realPath(packageRoot), join(root,'packages'))`）。
- `isTypeMetaSymbol()`（`analyzer.ts:2084`）判定 `@Remote`/`TypertRemoteService` 时，要求符号声明文件属于名为 `@deepseek-ai/dsh-typert-protocol` 的**已注册工作区包**。协议包在 `node_modules` 时一律返回 `false`，于是报 `publishes Remote artifacts but has no Remote methods`。
- 把协议包源码 vendored 到 `packages/` 后，又因 `Context.root` 静态符号在已发布 `@deepseek-ai/cordis@4.1.0` 中不存在（DSH vendor 源有该符号）而无法编译；继续 vendored cordis 会无限扩大复制面。
- 结论：这是上游生成器的**设计缺口**，应在 P7 前后向上游提「允许外部协议包/树外 workspace」的 seam；在它被接受前，使用降级路径。

### 3.2 降级路径（已验证）

`tooling/generate-via-checkout.mjs`：

1. 备份 `<checkout>/tsconfig.host.json`；
2. 把插件包复制到 `<checkout>/packages/extensions/nange-demo-remote`，写入扩展 `tsconfig.base.json` 的项目配置；
3. 在 references 中插入临时引用；
4. 运行 `pnpm exec tsx scripts/generate-typert.ts`（仓库生成器，`wrote 42 Typert artifact(s)`）；
5. 把 `typert.host.*`、`typert.remote-client.*` 拷回插件包；
6. `finally` 恢复 aggregate 并删除临时包。

约束：

- 必须在与运行 Host 同版本的 checkout 内生成（本轮 `39163dd30f`）；
- checkout 需已 `pnpm install`；
- 生成期间 checkout 的 `tsconfig.host.json` 短暂被修改（脚本保证恢复）；
- 生成的 `typert.remote-client.d.ts.map` 等文件必须列入包 `files`，否则生成器拒绝。

### 3.3 运行时验证

```
$ node fixtures/e2e-demo.mjs "http://127.0.0.1:3999/?token=…"
{
  "outcome": { "ok": true, "value": "echo:p2" },
  "banner": "P2 demo {\"ok\":true,\"value\":\"echo:p2\"}",
  "errors": [],
  "bootErrors": null
}
```

实现要点：

- Host 包默认导出 `TypertRemoteService` 子类，`super(ctx, 'demo')`，`@Remote('echo')`；
- 客户端先 `ctx.remote.$mount(remote)`，再用 `ctx.inject(['remote.demo'], scope => …)` 访问命名空间（直接读 `ctx.remote.demo` 会被 Cordis 的 inject 守卫拒绝）；
- 浏览器端只声明 `inject: ['remote']`，命名空间在 mount 后动态注入。

## 4. G2 证据与限制

- 产物格式：`window.__ModuleLoader__.load({ id, factory: require => { var module={exports:{}}; var exports=module.exports; …; return module.exports } })`。
- 包装策略：esbuild `format: 'cjs'`，externals = `PLATFORM_MODULES`（`react`、`react-dom`、`zod`、`@deepseek-ai/cordis`、`@deepseek-ai/dsh-client-store` 等）；生成 Remote 的 `remote-info` 内联（与官方 preset 行为一致）。
- 当前仅覆盖：无 CSS Modules、无资产、无代码分包、无 HMR 细节。正式 Git/编辑器插件若使用 CSS Modules / Monaco worker / 图片资产，需要：
  - 把官方 `packages/client/tsdown.client.ts`（1265 行）适配为插件仓 `tooling/client-preset.ts`，或
  - 向上游提「发布客户端插件构建 preset」 seam（[02 §8](../02-解耦改造方案.md) 已列）。
- Host 侧 `/plugins` 路由、`dsh.client.platform = web`、`exports["./client"]` 均按预期工作；页面无加载错误。
