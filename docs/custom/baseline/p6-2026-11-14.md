## 3. 浏览器与桌面

- 浏览器：官方 `ui-sidebar-browser` 仅在 `profileContext.name === 'desktop'` 时启用；Web 组合使用已有的 open-in-app 与文档预览，不引入自建 headed Chromium，符合 D3。
- 桌面：桌面 telemetry 与 `deepseek-harness-desktop` 服务行已在默认组合中，按 `profileContext.name` 门控；本环境没有桌面构建/签名产物，D4 的安装验收仍未做。
- 因此 P6 的「切换」在基础仓层面等价于：**保留上游行、删除自有实现**；不需要在基础仓新增任何 patch。

## 4. 切换清单（cutover）

前提：`refactor/main` 对 `base/upstream` 在 `packages/ apps/ vendor/ package.json pnpm-lock.yaml tsconfig*` 上零差异（当前为 0 行 diff）。

1. 以 `refactor/main` 为基线建立切换分支（或直接把 `custom/main` reset 到该基线并保留 `docs/custom`）。
2. 删除旧自有实现：
   - `apps/desktop` 下自研层与自定义 `packages/*`（以现状分析中的 834 文件清单为准）；
   - 所有旧 patch/overlay 文件与 `pnpm patch` 记录；
   - 旧终端、浏览器、桌面相关入口与设置项。
3. 用 profile 安装树外能力：`git`、`editor`（含 LSP）、`mermaid` 等 bundle；逐项 `dsh plugin --profile <p> add <绝对路径>`。
4. 执行门禁：
   - `pnpm install && pnpm run build && pnpm run typecheck`；
   - `dump-config` 与基线快照对比，确认终端/浏览器/桌面行来自上游；
   - `fixtures/` 全套 E2E：session（Mermaid+Git）、git provider、editor、editor-ops、lsp、terminal、mutations provider；
   - 卸载契约：移除 bundle 后 manifest/lock/dump 无残留（`link:` 开发残留单独记录）。
5. 记录切换前后的 `git rev-parse`、gate 输出与新 profile 的 `dump-config`，归档到 `docs/custom/baseline/`。

## 5. 未完成

1. **桌面端 D4 验收**：没有构建/安装/启动官方桌面产物，也没有在桌面 profile 下跑终端与浏览器 UI。
2. **浏览器工具**：未实际驱动官方浏览器能力（受桌面 profile 限制），仅有行与门控证据。
3. **旧实现删除**：仍在 `custom/main` 旧线，尚未执行 §4 的 reset 与删除。
4. **bundle 安装顺序风险**：P5 期间出现过一次 Mermaid `slot ... is not declared`，重装后恢复；切换清单第 4 步需要「干净 HOME 全量安装」复现，作为门禁而不是一次性人工修复。

## 6. 结论

P6 的架构结论已经成立：终端/浏览器/桌面全部采用上游实现，树外插件不接管这些能力；切换工作的剩余部分是**删除旧线与验收**，不是再写一套替代实现。终端 E2E 是第一个通过的切换证据，浏览器与桌面仍待环境支持。
