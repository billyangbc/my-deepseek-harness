## 3. 三个新约束

1. **Remote 方法名不能占用 `RemoteNamespaceService.prototype` 的成员**。`workspaceEdit/remove` 触发 `client api: method "workspaceEdit/remove" conflicts with its namespace service`（`remove` 是命名空间服务的内部方法）。改名 `deleteFile` / `moveFile` 后通过；同类需避开的还有 `has`、`installDirect`、`installScoped`、`assertMethodAvailable` 等。
2. **`workspaceFiles.list` 不接受空字符串路径**（报 `path is required`）；根目录要用 `'.'`。
3. **`workspaceFiles.read` 返回的 `text` 会丢掉文件末尾换行**，不能直接对 `text` 求哈希做写冲突检查。客户端改为 `readBytes` 取原始字节算 SHA-256；否则保存必然报 `file changed since it was read`。
4. **LSP 需要等待诊断落定**：`didOpen`/`didChange` 后不能立即读诊断，provider 以「下一次 `publishDiagnostics` 或超时」为界，超时回落最新值；否则 UI 首次打开几乎总是空诊断。
5. **文档句柄必须按 Session 隔离**：Remote 在 provider 句柄前加 `sessionId\0` 前缀，调用时校验前缀，防止跨 Session 操纵他人服务器文档。

另有一条待跟踪的激活问题：安装 `plugin-editor` 后的一次启动里 Mermaid 报 `slot "conversation.chat.markdown.fence" is not declared`；重新 `plugin add plugin-mermaid` 后恢复，当前 0 激活失败。疑似 bundle patch 顺序/批次重排，P7 的「干净环境全量安装」门禁会专门复现。

## 4. 与计划的偏差：CodeMirror 6 而非 Monaco

Monaco 的 ESM 入口携带大量 CSS 与 4 个 worker 资产；当前树外构建只产出单个 JS bundle，`/plugins` 路由只服务 `.svg/.png/.webp/.jpg` 资产，没有 worker/字体/样式产出通道。硬接 Monaco 会得到无样式、无 worker 的编辑器，或需要改造整个客户端构建协议。因此第一切片用 CodeMirror 6（无 worker、样式内联、963 KiB），先保证编辑/保存可用；Monaco 迁移列入后续。

## 6. 结论

写能力与编辑器面板已在树外跑通并保存成功；关键难点集中在「树外构建的 UI 资产能力」和「Remote 命名/客户端协议约束」，而不是文件写入本身。LSP 是下一个真正的架构工作量，Monaco 属于构建协议工作量，两者可并行评估。
