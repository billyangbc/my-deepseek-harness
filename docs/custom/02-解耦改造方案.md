# 解耦改造方案：基线上游化 + 功能插件化

- 配套阅读：[01-现状分析.md](./01-现状分析.md)、[03-实施计划.md](./03-实施计划.md)
- 上游对照版本：`deepseek-ai/deepseek-harness` `0.2.2-rc.3`（`39163dd30f`）
- 方案目标：满足任务 1/2/3 的三条硬要求，并给出可执行验收

## 0. 目标与验收定义

| 任务 | 可执行验收 |
|---|---|
| 1. 基础代码更新到最新版 | 仓库存在 `upstream` remote 与 `base/upstream` 镜像分支；`git diff --stat base/upstream -- packages apps vendor package.json pnpm-lock.yaml tsconfig*.json` 输出为空；`pnpm dsh --profile web --dump-config` 与上游同版本一致 |
| 2. 二次开发与基础完全解耦 | 上述「零差异」门禁成立；所有定制代码位于独立插件仓；官方包不出现定制符号（`grep` 门禁）；升级流程为 `git merge --ff-only upstream/master` |
| 3. 功能独立插件、可安装加载、卸载干净 | 每个功能有独立 bundle 包；`dsh plugin --profile <p> add <spec>` → 启用 → 使用 → 禁用 → `remove` 全链路脚本化通过；移除后 `--dump-config` 无残留行、页面无残留 UI/CSS/模块、无残留进程与存储键（白名单除外） |

## 1. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  基座（fork 仓库 = 上游镜像，零改动）                          │
│  upstream/master ──► base/upstream ──► custom/main            │
│                        （仅 docs/custom、CUSTOM.md）           │
│  安装形态：dsh CLI / 官方桌面应用（自带 profile 与插件管理）    │
└───────────────▲──────────────────────────────────────────────┘
                │  dsh plugin add（link / git）
┌───────────────┴──────────────────────────────────────────────┐
│  插件仓（独立 git 仓库，pnpm workspace）                       │
│  packages/                                                    │
│    plugin-git/       ── bundle：patch + 依赖                   │
│    git/  git-local/  api-git/  client-ui-git/                 │
│    plugin-editor/    ── bundle                                │
│    workspace-mutations/ workspace-mutations-local/            │
│    api-workspace-mutations/ lsp-editor/ lsp-editor-stdio/     │
│    api-lsp-editor/ client-ui-editor/                          │
│    plugin-markdown/  ── bundle                                │
│    client-ui-mermaid/                                         │
│  tooling/            ── 构建 preset + Typert 生成脚本          │
│  fixtures/           ── 安装/卸载验收脚本与样本 profile        │
└──────────────────────────────────────────────────────────────┘
```

三条原则：

1. **基座零改动**：不新增/修改官方 `packages/**`、`apps/**`、`vendor/**`、根构建配置。需要官方能力但上游没有 seam 时，优先向上游补 seam；次选把能力做成插件自有的 Service/Remote。
2. **一个功能一个组合包**：功能 = 一个 `dsh.bundle` 包（只含 patch、图标、locale、docs）+ 若干按能力角色拆分的实现包。组合包可独立安装/禁用/卸载，实现包不单独出现在 profile。
3. **只用公开扩展点**：客户端 UI 走右侧栏 `ctx.sidebarRightTabs` / slot / `conversation.chat.markdown.fence`；Host 能力走 `TypertRemoteService` + `@Remote`（自挂载）；Agent 工具走 `ctx.tools`；装配走 bundle patch 层。

## 2. 仓库与分支模型

### 2.1 仓库拆分

| 仓库 | 内容 | 谁发布 |
|---|---|---|
| `NanGePlus/my-deepseek-harness`（改为纯镜像 + 文档） | `upstream` 分支跟踪官方；`custom/main` = 官方 + `CUSTOM.md` + `docs/custom/**`；可选的 `delivery/` 说明与 profile 示例（不含代码） | 不发布代码 |
| `NanGePlus/dsh-plugins`（新建） | 所有定制功能、构建工具、验收脚本、插件文档 | Git tag（本轮不发布 npm） |

过渡期允许在 `my-deepseek-harness/extensions/` 内开发（减少双仓切换），但**不允许**把它接入根 `tsconfig` 或 `pnpm-workspace.yaml`；最终交付前必须迁出并删除该目录。

### 2.2 分支与升级

```sh
git remote add upstream https://github.com/deepseek-ai/deepseek-harness.git
git fetch upstream --tags
git branch -f base/upstream upstream/develop     # 镜像，只读（async 开发线：develop 领先 master）
git switch custom/main
git merge --ff-only base/upstream                # 因零差异，永远可快进
```

- 上游主开发线是 `develop`（本轮 `39163dd30f` 为 `0.2.2-rc.3`）；`master` 是发布镜像，同期滞后一个 rc（`e8f7b93a34`，`0.2.2-rc.2`）。镜像分支跟 `develop`，发布标签仍按 `dsh-v*` 记录。
- 每次升级：更新 `base/upstream` → `custom/main` 快进 → 插件仓升 `engines.dsh` 与 peer 版本 → 跑插件回归矩阵。
- 升级节奏建议跟随上游 `rc` 标签（本方案以 `0.2.2-rc.3` 为第一个基线）。
- 旧 `custom/main`（`c5ac2488d9`）打 tag `archive/custom-2026-09-05` 并保留分支 `archive/custom-main-v1`，只读备查。

## 4. 插件与包结构设计

命名使用自定义 scope（示例 `@nange`），**不得**使用 `@deepseek-ai` 作用域。每个功能一个 bundle；能力按 Service Definition / Provider / Consumer 拆分，便于替换与独立演进。

### 4.1 Git 插件

```
@nange/dsh-plugin-git                 # bundle：cordis.patch.yml + icon + locale + docs
@nange/dsh-git                        # Service Definition：ctx.git（类型 + 错误词汇）
@nange/dsh-git-local                  # Provider：经 ctx.subprocess / ctx.fs 调 git 命令
@nange/dsh-api-git                    # Remote Controller：ctx.gitController (@Remote)
@nange/dsh-client-ui-git              # 客户端：右侧栏 git tab + 面板 UI
```

- Remote 方法（按现有 13 个 RPC 重写，语义保持）：`status`、`workingTree`、`init`、`diffPreview`、`stage`、`unstage`、`discard`、`commit`、`push`、`addRemote`、`removeRemote`、`log`、`commitDiff`。
- 作用域：以 `WorkspaceId` 为参数（上游 `workspace-controller` 的 lookup 模式），错误码沿用 Remote 词汇：`git/not-found`、`git/unavailable`、`git/failed`、`git/path-not-found`。
- Provider 配置（不得硬编码）：`gitCommand`、`timeoutMs`、`maxOutputBytes`、`logPageSize`、`maxCommitDiffFiles`。
- 客户端：`ctx.sidebarRightTabs.register({ id: '@nange/dsh-client-ui-git', kind: 'git', title, guide })` + `sidebar.right.pane.tab` body；按 Session 的 workspace 绑定；提交草稿存 session-scoped 存储（不用全局 localStorage，避免卸残留）。
- dirty 路径守卫：与编辑器插件的 `ctx.editorDirty` 可选服务协作（双方都未安装时降级为无守卫）。

### 4.2 编辑器插件

```
@nange/dsh-plugin-editor               # bundle
@nange/dsh-workspace-mutations         # Service Definition：ctx.workspaceMutations（写/删/改名/移动/建目录）
@nange/dsh-workspace-mutations-local   # Provider：fs + sandbox policy + workspace 根边界
@nange/dsh-api-workspace-mutations     # Remote Controller
@nange/dsh-lsp-editor                  # Service Definition：ctx.lspEditor（文档同步 + 诊断 + hover）
@nange/dsh-lsp-editor-stdio            # Provider：stdio 语言服务器 + publishDiagnostics 归一化
@nange/dsh-api-lsp-editor              # Remote Controller：诊断/hover stream
@nange/dsh-client-ui-editor            # 客户端：文件树/多 Tab/Monaco/Markdown 预览/图片/Add to Chat
```

- 读、列、搜、监听**复用上游** `remote.workspaceFiles.*`（`read/readBytes/stat/list/search/changes`），不自建。
- 写能力自建：`writeFile`、`deletePath`、`renamePath`、`movePath`、`createDirectory`；必须经 `ctx.sandboxPolicy` 与 workspace 根边界（越界返回 `workspace/path-out-of-bounds` 语义）。
- LSP：独立 seam，不修改上游 `lsp`；Provider 保留文档状态与版本化诊断（移植 fork 的 `lsp-editor` 与 `lsp-stdio` 诊断逻辑）。
- UI：`sidebarRightTabs.register({ kind: 'editor', patterns: ['dsh-resource://file/**'] })`；文件树复用上游 `sidebar.files.tree` Factory（若 Factory 可复用），否则自带轻量树；Markdown 预览态用 TipTap；Add to Chat 通过 `ctx.inputTriggers.registerSource` 注册引用源并在组合框插入 pill。
- Tab 布局持久化交给上游 `ui-sidebar-right`（`dsh.sidebar-right.v1.<sessionId>`），不另建全局 store。

### 4.3 Markdown / Mermaid 插件

```
@nange/dsh-plugin-markdown
@nange/dsh-client-ui-mermaid
```

- 注册 `conversation.chat.markdown.fence` 的 `hoc` 层，`entryKey: 'mermaid'`，只接管 mermaid fence，其余 fence 透传 `children`（上游已提供 fallback 代码块）。
- lightbox 缩放范围对齐上游 `DOCUMENT_ZOOM`（0.25–4，step 0.25），便于未来共用。

### 4.4 归档：有头共享 Chromium（不交付）

决策 D3 已确认改用上游官方浏览器能力：人类侧用 `ui-sidebar-browser`（Web 沙箱 iframe / Desktop `<webview>`），Agent 侧用官方 `browser-use` 组合包（Playwright/Chrome DevTools/Stagehand MCP）。

自制部分整段归档到 `archive/browser-shared-headed` 分支，不迁移、不维护：

- `packages/client/ui-browser`、`packages/browser/tool-browser`；
- `apiproxy` 的 `browser-registry.ts`、`browser-delivery.ts`、`browser-page-scripts.ts`、`browser-navigation-url.ts`；
- 桌面侧 `BrowserView` / occupant bounds / CDP 附着逻辑。

若未来产品重新要求「人机同面」，需要先推动上游桌面壳提供浏览器宿主 seam，否则只能独立分叉桌面应用；该评估不在本轮范围。

## 5. 关键 seam 与缺口

| 编号 | 缺口 | 影响 | 对策 | 验证（PoC） |
|---|---|---|---|---|
| G1 | **树外 Typert Remote 代码生成**：生成器要求协议包位于 `<root>/packages` 且依赖 vendored cordis 源码 | Git/编辑器插件的 Host Remote 无法纯树外生成 | **P2 结论：采用降级路径**——插件仓 `tooling/generate-via-checkout.mjs` 临时把包放进基座 checkout 生成 artifacts、运行时树外安装；同时向上游提「树外 workspace/协议包」seam | 已通过：Host 注册 + Client `$mount` + `echo` 调用返回 `{ok:true}` |
| G2 | **树外 client bundle 构建**：preset 在 `packages/client/tsdown.client.ts`，未发布 | 客户端插件无法构建 | **P2 结论：最小实现通过**——esbuild + loader closure-factory 包装（externals 取 `PLATFORM_MODULES`，生成 Remote 内联）；CSS Modules/资产/分包场景再适配官方 preset 或推动上游发布构建 preset | 已通过：页面加载 bundle 并调用 Remote |
| G3 | 上游文件写能力缺失（`workspace-files` 只读） | 编辑器无法保存/增删移 | 自有 `workspaceMutations` 能力（不改官方） | P5 集成测试（越界/符号链接/只读盘） |
| G4 | 上游 LSP 无编辑器诊断；`LspConnection` 丢弃服务端通知 | Monaco 无诊断 | 自有 `lspEditor` seam + **自带 stdio 传输**（不复用上游通知被丢弃的连接层）；同时向上游提「通知订阅口」seam | P5 pyright/tsserver 冒烟 |
| G5 | 有头共享浏览器无上游 seam | 该能力不交付 | 决策 D3：归档，采用官方浏览器能力 | 不适用 |
| G6 | Markdown fence 注入点确认 | Mermaid 能否纯插件 | 已确认：`conversation.chat.markdown.fence`（hoc，`entryKey: lang`） | P3 |
| G7 | Add to Chat 组合框插入 | 选区 → pill | `ctx.inputTriggers.registerSource` + 引用服务；若插入 API 不足，退化为「插入引用文本」 | P5 |
| G8 | preset 工具行（本轮不需要） | 若未来插件要注册 Agent 工具并进发行版预设 | 上游 patch 不能局部追加 preset row 的 `config.plugins`（`applyEntryPatches` 只索引顶层与 `group` 数组），只能整份重述 preset row，或采用「发行版常驻行 + `disabled: !!js '!ctx.get(...)'`」模式。本轮 Git/编辑器/Mermaid 均不注册 Agent 工具；浏览器工具改用上游 `browser-use` 组合包，自带装配 | 不在 P4/P5 范围；需要时单独立项 |
| G9 | 桌面插件安装 | 桌面 profile 由官方应用管理 | 使用官方桌面「插件管理」（自带 pnpm）安装同一 bundle；不新增 profile 模板 | P6 |

## 6. 安装、加载与卸载契约

### 6.1 安装形态

```sh
# 开发：链接本地插件仓
dsh plugin --profile web add ./dsh-plugins/packages/plugin-git
# 发布：Git tag（本轮不发布 npm）
dsh plugin --profile web add 'git+https://github.com/NanGePlus/dsh-plugins.git#<commit>&path:packages/plugin-git'
```

bundle 的 `package.json` 必须包含：

```json
{
  "name": "@nange/dsh-plugin-git",
  "version": "0.2.2-rc.3",
  "engines": { "dsh": ">=0.2.2-rc.3 <0.3.0" },
  "dsh": { "bundle": { "patch": "./cordis.patch.yml" } },
  "peerDependencies": { "@deepseek-ai/cordis": "^0.2.2", "@deepseek-ai/dsh-typert-protocol": "^0.2.2-rc.3" },
  "files": ["cordis.patch.yml", "icon.svg", "locale/*.json", "docs", "lib/**", "src"]
}
```

### 6.2 卸载干净契约（三层）

| 层 | 由谁清理 | 内容 | 验收方式 |
|---|---|---|---|
| 框架自动 | Plugin Manager / Loader / client-modules | profile 依赖与 `bundles` 列表、Loader 行、Cordis effect（服务、slot、tab type、工具、Remote 命名空间）、client 模块与 `<style data-plugin>`、插件设置命名空间 | `dsh --profile p --dump-config` 无该行；页面无该 tab/样式；控制台无该插件请求 |
| 插件自清 | 插件 `ctx.effect` 的 disposer | 子进程/PTY（随服务 dispose 关闭）、文件监听、流式连接（abort）、定时器、编辑器 dirty 状态、会话级草稿 | 卸载后 `ps`/端口无残留；无未捕获异常；重装后行为正常 |
| 设计上不可清（文档声明） | — | 历史 Session 日志中的旧事件（若新增事件必须 `ignorable: true`）、用户文件、`$DSH_HOME` 中与插件无关的共享数据 | 文档列出；迁移脚本只在需要时提供 |

**存储策略**：插件不写全局 `localStorage`；UI 布局用上游侧栏 store；草稿用 session-scoped key（`nange.editor.draft.<sessionId>`），卸载后按 session 自然过期。这是「可卸载干净」的关键设计约束。

**Session 事件**：第一交付的 Git/编辑器均不新增 session event。若未来新增，必须 `ignorable: true` 并随事件携带版本，保证无插件时日志可加载。

### 6.3 卸载验收脚本（`fixtures/uninstall-check.ts`）

1. 用干净 `DSH_HOME` 创建 profile `verify`；`dsh plugin add <bundle>`。
2. `--dump-config` 记录行集合；断言包含 bundle 行、无 schema 告警。
3. 启动 Web（headless 模式即可），断言版本与健康检查通过；对客户端插件用 Playwright 打开页面，断言 tab 存在、无 console error。
4. `dsh plugin remove <bundle>`；再次 `--dump-config`，断言行集合与安装前完全一致。
5. 重启进程，断言 profile 目录无该包、`node_modules` 无残留、无子进程。
6. 重装并禁用（`disabled: true`），断言不加载但可再次启用。

## 7. 版本与兼容策略

| 维度 | 规则 |
|---|---|
| 基线 | 每个上游 `rc` 标签对应一个插件版本线（如插件 `0.2.2-rc.3` ↔ 上游 `0.2.2-rc.3`） |
| 声明 | bundle 用 `engines.dsh` 精确区间；实现包用 peerDependencies（+ devDependencies 供构建与单测） |
| 客户端 bundle | 必须用与运行 Host **同一 release** 的构建产物；插件 README 标注「与 Host release 绑定」，禁止跨 release 混装 |
| 依赖 | Monaco/TipTap/Mermaid 等第三方库放插件 `dependencies`；dsh 包放 peer + dev |
| 发布 | Git tag（`v<dsh-version>-<plugin-rev>`）；本轮不发布 npm，安装用 Git spec 或本地 link；`CHANGELOG` 记录行为差异 |
| 弃用 | 插件包 `deprecated` 说明替代方案；跨大版本不承诺兼容 |

## 8. 向上游补 seam（可选但高价值）

| 提案 | 价值 | 规模 |
|---|---|---|
| 发布 `@deepseek-ai/dsh-client-plugin-build`（client bundle preset + externals 清单） | 第三方客户端插件可独立构建 | 小（抽包 + 文档） |
| 提供 `WorkspaceTypertGenerator` 的树外 CLI/文档 | 第三方 Host Remote 可独立生成 | 中（CLI + fixture） |
| `workspace-files` 增加 mutation 命名空间（或独立 workspace-mutations 包） | 人类编辑写入成为官方能力 | 中（与沙箱策略对齐） |
| `lsp` 增加编辑器诊断 seam（`lsp-editor`） | 官方编辑器能力 | 中 |
| 桌面壳暴露浏览器宿主 seam（BrowserView/WebView 扩展点 + bounds + CDP） | 有头共享浏览器才能零差异落地 | 大（需产品共识） |

策略：先用自有实现交付；每完成一项 PoC，向上游提一条 Proposal/PR。上游接受后删除自有实现，进一步减少私有面。

## 10. 验收门禁（在插件仓 CI 与基座仓 CI 各跑一部分）

1. **零差异门禁**（基座仓）：`git diff --stat base/upstream -- packages apps vendor package.json pnpm-lock.yaml tsconfig.base.json tsconfig.host.json tsconfig.client.json` 为空。
2. **定制符号门禁**：`rg '@nange|nange-' packages apps` 无命中。
3. **插件构建门禁**：`pnpm build`（tsc + tsdown + typert 生成）通过；`publint`/`knip` 不外泄 dsh 私有 API。
4. **安装矩阵**：每个 bundle × {web, desktop} 的 add/enable/disable/remove 脚本通过。
5. **功能回归**：Git（状态/暂存/丢弃/提交/推送/日志）、编辑器（打开/编辑/保存/外部变更/诊断/Add to Chat）、Mermaid（渲染/lightbox）各有 e2e 或快照。
6. **卸载审计**：`fixtures/uninstall-check.ts` 全绿；进程/端口/存储残留为零（白名单除外）。
7. **桌面冒烟**：上游桌面打包产物中安装插件 bundle，启动、使用、卸载各一次。

## 11. 风险与缓解（方案层）

| 风险 | 缓解 |
