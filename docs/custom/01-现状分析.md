## 0. 结论先行

1. **当前 fork 与上游已经结构性错位，不能再用「合并上游」的方式升级。** 分叉点在上游 `47f943859b`（2026-08-13），上游此后有 **14,926** 个提交、改动 **23,204** 个文件；fork 的 219 个被改官方文件中，**211 个（96.3%）也被上游改过**。更关键的是，fork 依赖的三个官方结构已被上游整体替换：
   - `packages/host/apiproxy`（fork 全部自定义 RPC 的宿主）在上游已删除，改为 `packages/api/*`（Typert Remote）+ `packages/host/webserver`；
   - `packages/client/ui-conversation` 的「详情栏/工具箱」在上游已删除，改为右侧栏 `ctx.sidebarRightTabs` 标签类型注册；
   - 桌面交付在上游已内置（`apps/desktop`、`apps/desktop-host`、`apps/desktop-publisher`），与 fork 自建的 Electron 壳重叠。
2. **二次开发规模约 6.8 万行新增**（不含 `.agents/notes` 与 docs），集中在 5 个功能区：文件编辑器、Git 面板、人类终端、内嵌浏览器、Electron 桌面壳。其中约 **1.47 万行**落在官方包 `packages/host/apiproxy` 内部，约 **0.35 万行**是官方 UI 壳层（`ui-conversation`、`ui-primitives`、`ui-tool`、`ui-layout`）的侵入式修改。
3. **五功能中有三项已被上游原生能力覆盖或超越**：终端（`api/terminal-controller` + `client/ui-sidebar-terminal`，Session 级 PTY、Agent 终端共享、断线恢复）、文件浏览/预览（`api/workspace-files` + `ui-sidebar-files` + `ui-sidebar-documentpreview`）、桌面壳（官方 Electron 应用）。**Git 工作区面板与 Monaco 编辑器是 fork 的独有价值**；有头共享 Chromium 浏览器是 fork 的独有产品形态，但成本最高。
4. **上游已经具备把功能做成独立可安装插件/组合包的全部运行时机制**：bundle（`dsh.bundle`）+ profile（`dsh.profile`）+ `dsh plugin add/remove` + Plugin Manager + 客户端插件 `dsh.client` 与 `/plugins` 资源路由 + 官方可选/实验组合包。并且 `packages/experimental/client-ui-forge` 已经给出了「功能包自带 Host Remote + Client 侧边栏面板 + 组合包」的完整范例，可作为改造模板。
5. **唯一真正的树外能力缺口是「树外 Typert Remote 代码生成」与「树外 client bundle 构建 preset」**。这两项决定「完全解耦」能否落地，必须在实施前用 PoC 验证（详见方案文档 §5、计划文档 P2）。
6. **推荐路线：重基线（re-baseline）+ 按功能插件化移植**，而不是把上游 merge 进 `custom/main`。目标态是：fork 仓库对上游 `packages/ apps/ vendor/` **零差异**，所有二次开发以独立组合包安装在 profile 中，可 `dsh plugin remove` 卸载干净，上游升级退化为 `git merge --ff-only upstream/master`。

## 3. 耦合点剖析

### 3.1 Host 层：`packages/host/apiproxy` 内的自定义 RPC（最重耦合）

fork 在官方 `host/apiproxy` 中新增 37 个文件、修改 18 个文件，自建了一套 Zod 校验的四象限 RPC 消息模型（请求/响应、服务端推送、流），并在 `src/api/host.ts` 里新增约 49 个业务方法（文件 8、Git 13、终端 7、浏览器 18、LSP 3）：

| 域 | RPC 方法 | 传输 |
|---|---|---|
| 文件 | `readFile`、`writeFile`、`listWorkspaceEntries`、`deletePath`、`renamePath`、`movePath`、`createWorkspaceDirectory`、`watchPath` | 一元 / `watchPath` 走 WebSocket |
| Git | `gitStatus`、`gitWorkingTree`、`gitInit`、`gitDiffPreview`、`gitStage`、`gitUnstage`、`gitDiscard`、`gitCommit`、`gitPush`、`gitAddRemote`、`gitRemoveRemote`、`gitLog`、`gitCommitDiff` | 一元；`gitCommit({push})` 与页面加载类 RPC 免除 30s 一元超时 |
| 终端 | `terminalProfiles`、`terminalSpawn`、`terminalWrite`、`terminalResize`、`terminalKill`、`terminalList`、`terminalStream` | 一元 + SSE |
| 浏览器 | `browserList`、`browserCreateTab`、`browserCloseTab`、`browserSelectTab`、`browserShowWindow`、`browserNavigate`、`browserGoBack`、`browserGoForward`、`browserReload`、`browserSnapshot`、`browserClick`、`browserType`、`browserScroll`、`browserSelectOption`、`browserResizeViewport`、`browserSendPointer`、`browserSendKeyboard`、`browserWatchScreencast` | 一元 + SSE；Playwright 有头 Chromium |
| LSP | `lspSyncDocument`、`lspHoverDocument`、`lspCloseDocument` | 一元 |
| 桌面 | `browserDelivery: desktop` 配置、`DesktopBrowserSurface` hook | 进程内 |

耦合事实：

- 这些 RPC 依赖 fork 自建的 schema/错误码表（`src/api/rpc.ts`、`src/api/rpc.schema.ts`），并与 `packages/client/connection` 的客户端 schema 成对维护；上游 0.2.2 已删除该包与这套模型，替换为 `TypertRemoteService` + `@Remote` + `api/gateway`。
- 新增第三方依赖 `playwright`（浏览器 RPC），属于 Host 进程内的重依赖。
- RPC 与 Workspace/Session 身份强绑定（`workspaceId`、`sessionId`），错误码里含 `terminal-unavailable`、`browser-tab-not-found` 等产品语义。

### 3.4 桌面栈

fork 自建：`apps/desktop`（Main、`dsh://` 协议、preload、IPC bridge、BrowserView 管理、退出守卫、窗口状态、菜单、brand）、`apps/desktop-host-pkg`（打包闭包）、`packages/bundle/desktop-app`（desktop profile 组合包）、`apps/cli` 启动器、`scripts/{dev-desktop,prepare-desktop-packaging,run-electron-builder,smoke-desktop-packaging}`、`.github/workflows/desktop-packaging.yml`。

上游 0.2.2 已内置完整桌面应用：`apps/desktop`（60+ 源文件、更新器、品牌、欢迎窗口、平台 IPC）、`apps/desktop-host`（Desktop Host）、`apps/desktop-publisher`（发布）、`docs/user/guide/desktop-uninstall-cleanup.md`、保留 profile `desktop`、`packages/host/authentication-desktop`。并且浏览器形态是客户端 `<webview>`/iframe（`ui-sidebar-browser`），不是 Host BrowserView。

逐项对比的结论（证据见 [research/s3-desktop.md](./research/s3-desktop.md)）：

- **上游已原生、自制可删的 12 项**：Host 子进程启动与致命恢复、HTTP `/api` + WS carrier、父→子一次性凭据认证、`dsh-app://` SPA 托管与插件 bundle 转发、单实例、退出确认（2s 超时）、托盘/多语言菜单/快捷键、打包/签名/公证/自绘 NSIS 安装器/electron-updater/强制更新/发布、卸载清理、自带 pnpm 的插件管理、崩溃报告、窗口 `<webview>` 浏览器租约。
- **自制真正独有的 2 项**：① Agent 与人类共用同一有头 Chromium（`BrowserView` + `connectOverCDP` + occupant bounds + `host.browser.*` + `tool-browser`）；② 窗口几何持久化（约 60 行，上游固定 1280×820）。
- **自制与上游直接冲突的 3 项**：`desktop` profile 名被上游 CLI 保留（`apps/cli/src/args.ts:84` 会报错，且 `$DSH_HOME/profiles/desktop` 归官方桌面所有）、`dsh:` scheme 被上游占用为 OS 深链、`appId: ai.deepseek.harness.desktop` 与官方安装包同命名空间。
- **自制壳的安全与生命周期缺陷**（迁移时应放弃而不是搬迁）：CDP 端口 `9222` 常开且 `remote-allow-origins=*`；`ipcMain.handle` 不校验 sender frame；`attach` 模式可把任意 http(s) 页面载入带 preload 的主窗口；Host 与壳同进程、插件异常即整壳崩溃；`exit-guard` 的退出请求无超时且 `close` 被 `preventDefault()`，渲染层卡死时窗口无法关闭；打包完全不签名。

因此「有头共享 Chromium」若要保留，必须解决一个上游缺口：BrowserView 的创建发生在 Electron Main，profile 插件（Host 进程）无法直接创建；除非上游提供桌面壳 seam，否则只能继续分叉 `apps/desktop` 或放弃。

### 4.1 关键范例：`packages/experimental/client-ui-forge`

上游实验包 `@deepseek-ai/dsh-experimental-client-ui-forge` 是「功能包自带 Host Remote + 客户端面板 + 组合包」的完整模板：

- `package.json` 同时导出 `./client`、`./remote`、`./typert`、`./types`，`dsh.client.inject` 声明依赖的客户端插件；
- Host 侧 `class ForgePanelController extends TypertRemoteService`，20+ 个 `@Remote`（含 `mode: 'stream'`）；
- Client 侧 `src/client/mount.ts` 用 `await ctx.remote.$mount(contribution)` 自行挂载生成的贡献，再用 `ctx.inject(['remote.forgePanel', ...])` 注册 UI；
- 组合包 `packages/experimental/forge-bundle/cordis.patch.yml` 只做 `insert` 行，`package.json` 声明 `dsh.bundle.patch` 与 `files`。

这条路径绕开了 `packages/api/remotes` 的显式程序集限制，也证明客户端包可以自带 Remote 命名空间。**本方案的 Git/编辑器插件应照此结构组织。**

### 6.1 解耦度评级（当前状态）

| V1 文件编辑器 | `apiproxy` RPC + `client/runtime` + `connection` | `conversation.details.editor` slot + DetailsPanel + locale + Add to Chat 改造 | `tsconfig` paths、`web-app` patch、web seed | 红（深度耦合） |
| V2 Git 面板 | 同上（13 个 RPC） | `conversation.details.git` slot | 同上 | 红 |
| V3 终端 | 同上（7 个 RPC） | `conversation.details.terminal` slot | 同上 | 红（但可整体删除） |
| V4 浏览器 | `apiproxy` Playwright + `browser-delivery` + `connection` IPC | `conversation.details.browser` slot | desktop profile、CLI、打包脚本 | 红 |

### 6.2 卸载残留清单（若只删定制包，当前会留下）

| 层 | 残留 | 后果 |
|---|---|---|
| Host RPC | `apiproxy` 内 37 个文件与 `host.ts`/`rpc.ts` 的方法、错误码、config 字段 | 客户端 schema 失配；loader 行失效；类型检查失败 |
| 装配 | `client/connection` schema 方法、`client/runtime` 转发、`api/remotes` 导出 | 类型/运行时残留方法 |
| UI 壳层 | `ui-conversation` 的 5 个 details slot 声明、DetailsPanel、locale key、Add to Chat 投影 | 删除插件后面板槽仍在、文案仍在、类型仍要求 |
| bundle | `packages/bundle/web-app/cordis.patch.yml` 的 5 行、`package.json` 依赖 | 启动时报找不到模块 |
| preset | `apps/cli/config/agent-presets/{standard,code,cordis}/agent.cordis.yml` 的 `tool-browser` 行 | 预设启动失败或工具缺失告警 |
| 构建 | `tsconfig.base/host/client` paths、`vitest.config.ts`、`pnpm-lock.yaml`、`apps/web` 快照与 seed | 构建失败或测试失败 |
| 桌面 | `apps/cli` 的 `desktop` 子命令与 electron 依赖、`boot/app-boot` desktop 模板、打包脚本与 workflow | CLI/打包残留 |
| 运行时状态 | `localStorage`：`dsh.browser.panel.v1` 等浏览器/终端 Tab store、Git 草稿 | 用户数据残留（无自动清理） |
| 进程 | Playwright Chromium、PTY、`watchPath` 监听 | 若 dispose 未覆盖则泄漏 |
| Session 日志 | 自定义 RPC 不写日志，风险低；若未来新增自定义 session event，必须 `ignorable: true` | 否则旧日志在新版无插件时无法重放 |

### 6.3 根因归纳

1. **扩展点选择错误**：V1–V4 全部挂在「详情栏」这个 fork 自己新增的壳层上，而不是官方 slot/右侧栏；导致任何插件都必须先改官方 UI。
2. **传输层自建**：把业务 RPC 塞进官方 `apiproxy` 的 schema，而不是作为独立 Remote 命名空间贡献；导致官方重构即全量失效。
3. **装配层侵入**：profile 模板、CLI 子命令、bundle 行、tsconfig paths 都直接改官方文件；这些文件的变动频率最高。
4. **缺少卸载契约**：没有「删包即干净」的设计，状态散落在 localStorage、官方 locale、官方 slot 声明中。

## 8. 对本轮任务的直接含义

- **任务 1「更新基础代码到最新版」**：不能 merge；应 re-baseline 到 `39163dd30f`（`0.2.2-rc.3`），旧 `custom/main` 打 tag/branch 冻结备查。
- **任务 2「与基础代码完全解耦」**：以「官方 `packages/ apps/ vendor/` 零差异」为可执行验收门禁；所有 Host 能力走独立 Remote 命名空间，所有 UI 走右侧栏 tab type/slot，所有装配走 bundle patch。
- **任务 3「各功能独立插件、可独立安装加载、可卸载干净」**：采用上游 bundle/profile/Plugin Manager 机制；每个功能一个组合包 + 若干能力包；卸载验收脚本化（安装→启用→使用→禁用→移除→无残留）。
